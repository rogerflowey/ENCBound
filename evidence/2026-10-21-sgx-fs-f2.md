`repo-local-v1` images and independently verifies the pinned application
source hashes.

## F2 result

`f2_control.py` compiles the host against each existing generated bridge and
runs `host <signed> f2`. It creates sixteen 4096-byte files with unique
`MARKER-FILE-NN-SECRET` prefixes, then reads `fileNN` at offset 4095 with
length 4096.

| Profile | Result |
| --- | --- |
| BASELINE | 14 host-visible cross-file plaintext leaks |
| RADIX_ONLY | `SIGILL`; checked source extent rejection |
| MAC27 | `SIGILL`; checked source extent rejection |
| MAC27-high | `SIGILL`; checked source extent rejection |

BASELINE output (one of fourteen rows):

```text
F2_CALL victim=file01 offset=4095 size=4096
F2_READ victim=file01 status=0 result=4096
F2_LEAK victim=file01 offset=17 marker=MARKER-FILE-02-SECRET
```

Protected attribution (RADIX_ONLY; MAC27 and MAC27-high are the same check at
their configured bases):

```text
Program received signal SIGILL, Illegal instruction.
encbound_abort (code=4) at sdk/platform_layout.c:459
#1 encbound_require (... width=width@entry=4096, kind=kind@entry=1)
   at runtime/capability.c:186
#2 encbound_memcpy (... n=4096) at runtime/adapters.c:28
#3 FileSystem::read_data (... offset=4095, size=4096)
   at .../utils/filesystem.cpp:190
#4 FileSystem::read (... offset=4095, length=4096)
   at .../utils/filesystem.cpp:207
#5 ramfs_get (... offset=4095, size=4096) at .../Enclave/Enclave.cpp:43
```

This is the F2 boundary case: the application copy is redirected to
`encbound_memcpy`, whose source `encbound_require(..., 4096, READ)` sees a
4096-byte extent starting one byte before the block slot end and terminates
with `ENCBOUND_ERR_RANGE` (code 4). The original application access is still
at `filesystem.cpp:190`; the enforcement is the checked library adapter, not a
compiler-inserted check at the original `memcpy`.

## What is established

* BASELINE returns adjacent file-block plaintext through the normal
  `[out, size=size]` ECALL output path.
* RADIX_ONLY, MAC27 and high-base MAC27 reject the same request with an
  attributed checked-extent failure before the copy.
* The ordinary 83-ECALL host path still passes in all four images after the
  host change.

## Limits

* SDK SIM only; no SGX hardware, FUSE mount, timing or performance result.
* The four images are the fresh `apps/sgx-fs/run.py` outputs from the
  self-contained `repo-local-v1` build.
* No full exploit, control-flow hijack or extraction of a production secret is
  claimed. The leaked plaintext is harness-created adjacent file data; the
  finding is the host-visible out-of-bounds read channel.
